3. Pros & Cons by Tool

Chrome DevTools (Lighthouse) — Pros

  • Built into Chrome, no extension or account needed
  • Scores accessibility alongside Performance/Best Practices/SEO, so you see it in context of overall page health
  • Fast, one-click "Analyze page load"

Chrome DevTools (Lighthouse) — Cons

  • Shallow automated checks - gave both YouTube and Twitch a perfect 100 despite likely real issues on such large, complex sites
  • No live overlay on the page; you don't see issues in context without switching panels
  • Doesn't point at the exact failing element the way Axe does

Axe DevTools — Pros

  • Cites the exact WCAG success criterion (e.g. 1.4.3) and computes the precise contrast ratio vs. the ratio required
  • Shows the actual violating HTML snippet inline, so fixes are unambiguous
  • Handled every site I tested, including JS-heavy ones like YouTube, without issue

Axe DevTools — Cons

  • Only reports "automatic" issues by default; deeper "Guided Tests" (keyboard nav, screen reader flow) are gated behind sign-up
  • Dense, developer-facing UI — less skimmable at a glance than Silktide's

Silktide — Pros

  • Plain-language explanations of each issue (good for non-technical stakeholders)
  • Simple overlay grouped by issue type with counts — easy to scan at a glance
  • Caught the same contrast problems Axe did, confirming the finding

Silktide — Cons

  • Reliability: crashed/failed to scan both YouTube and Twitch entirely — couldn't handle JS-heavy, large sites that Axe and Lighthouse scanned without trouble
  • Flags generic full-website conventions (like "skip to content") that don't map cleanly onto a single-page context like an HTML email, where that pattern isn't standard practice or well-supported by email clients
